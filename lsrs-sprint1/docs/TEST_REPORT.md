## 브라우저·카메라 검증 범위

실제 페이지에서 가입→개발용 메일함→인증 링크→로그인→예약 확인→QR 이미지 체크인→퇴실을 실행했습니다. 관리자 페이지의 QR 표시·기간 전환과 학생 화면의 최신 정책 반영도 확인했습니다. 브라우저의 처리되지 않은 JavaScript 오류는 0건입니다. 로컬 자산만 요청하며 외부 CDN에 의존하지 않습니다.

카메라 권한 거부를 주입했을 때 실패 안내가 나오고 예약이 RESERVED로 유지됐습니다. 별도로 Chromium의 가상 카메라에 QR Y4M 영상을 공급해 **getUserMedia → video → canvas → jsQR → 실제 체크인 API**를 끝까지 검증했습니다. 성공 후 카메라 트랙 종료도 확인했습니다. 이 결과가 실제 휴대폰 카메라의 촬영 품질·브라우저별 호환성 검증을 대신하지는 않습니다.

## SMTP·재시작 결과

실제 JavaMailSender를 로컬 TCP SMTP 수신 서버와 연결했습니다. 받은 메일 본문의 실제 인증 토큰으로 계정을 활성화했습니다. SMTP가 451로 거부하면 가입 계정은 PENDING, 응답은 deliveryStatus=FAILED, 로그인은 거부되는 것을 확인했습니다. 외부 사람에게 이메일을 보내지 않았습니다.

local 프로필의 실제 시각으로 가입·인증·예약·정책 변경 후 프로세스를 종료하고 같은 파일 DB와 랜덤 서명 키로 재시작했습니다. 계정·예약·정책·입실 기한·기존 JWT·QR 이미지가 보존됐습니다.
